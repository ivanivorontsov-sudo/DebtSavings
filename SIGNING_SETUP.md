# Постоянная подпись Android-релизов

Релизные APK подписываются одним приватным ключом, который хранится вне репозитория.

В GitHub откройте **Settings → Secrets and variables → Actions** и создайте два Repository secrets:

- `RELEASE_KEYSTORE_BASE64` — полное содержимое файла `DebtSavings-release.jks.base64` (одна строка).
- `RELEASE_KEYSTORE_PASSWORD` — пароль из файла `DebtSavings-signing-info.txt`.

Alias уже задан в Gradle: `debtsavings`. Пароль ключа совпадает с паролем хранилища. Сам файл JKS и пароль нельзя коммитить в репозиторий или отправлять в публичные Issues.

Ожидаемый SHA-256 сертификата: `F2:39:44:CF:42:0B:CE:7F:F9:0D:D5:3E:8E:69:72:B0:B4:CE:88:97:23:E7:89:78:17:3D:1C:7B:FA:7A:3A:2D`. Workflow проверяет этот отпечаток перед публикацией APK.

## Однократный переход с прежней подписи

Сборки 1.2.0 создавались стандартным debug-keystore на временном GitHub Actions runner. Его приватный файл не сохранялся, поэтому новая постоянная подпись не может совпасть с уже установленным сертификатом.

Перед переходом экспортируйте данные приложения в JSON. Затем один раз удалите старую установку и установите APK 1.3.0, собранный с постоянным ключом. Импортируйте JSON-резервную копию. После этого все релизы этой линии будут подписываться тем же сертификатом и обновляться поверх установленного приложения без удаления.
