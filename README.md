# DebtSavings — Долг и накопления

Android-приложение для локального учёта долгов, свободных средств, накопительных целей и регулярных подписок.

**Версия 1.2.0** · пакет com.example.debtsavings

## Что умеет

- Несколько кредитов и отдельный учёт тела долга, начисленных процентов и комиссий.
- Журнал операций с привязкой к конкретному кредиту.
- План погашения по двум стратегиям: **лавина** (сначала самая высокая ставка) и **снежный ком** (сначала наименьший остаток).
- В расчёте плана минимальные платежи идут по всем долгам; дополнительная сумма направляется на выбранный долг, а после его закрытия освободившийся платёж переносится на следующий.
- Сценарная оценка срока погашения и будущих процентов.
- Накопительный счёт: ежедневное начисление, пользовательская цель, ежемесячный взнос и цель резервного фонда.
- Календарь платежей, напоминания и учёт подписок.
- JSON-резервная копия и восстановление через системный выбор файлов.

## Как рассчитываются долги

Платёж распределяется в порядке: комиссии → начисленные проценты → тело. Для оценки плана используется упрощённая модель APR/12 на остаток тела долга. Она сравнивает стратегии, но **не заменяет график банка**: будущие комиссии, штрафы, плавающие ставки, дневные правила начисления и индивидуальные условия договора могут изменить результат.

«Лавина» обычно уменьшает суммарные проценты, так как быстрее гасит более дорогой долг. «Снежный ком» быстрее убирает небольшие остатки и может психологически помогать соблюдать план. Во всех случаях продолжайте выполнять реальные обязательные платежи по договорам.

Переключатель автоматической отметки платежа относится только к внутреннему журналу приложения. Он **не переводит деньги и не оплачивает кредит в банке**. По умолчанию выключен.

## Накопления и резерв

Свободные операции и проводки кредитов учитываются раздельно: кредитная задолженность не вычитается из баланса накоплений. Прогноз цели использует заданный ежемесячный взнос и приблизительную месячную капитализацию, эквивалентную APR/365. Реальный банковский доход зависит от тарифа, минимального остатка, пополнений, снятий, налогов и условий банка.

Размер резерва не зашит в приложение как универсальная норма. Укажите свои необходимые ежемесячные расходы и подходящее количество месяцев. Даже небольшая резервная сумма может быть полезной; цель должна учитывать вашу ситуацию и стабильность дохода.

## Конфиденциальность и резервные копии

- Данные приложения хранятся локально в Android SharedPreferences.
- Приложение не подключается к банковским счетам и не получает выписки.
- Экспорт JSON не шифруется. Храните резервную копию в защищённом месте и не включайте в неё пароли, PIN, CVV или полные номера карт.
- На первом запуске приложение не создаёт фиктивные кредиты и не заполняет реальные остатки примерами.
- Все суммы и даты вводятся пользователем; перед оплатой сверяйте их с приложением банка и договором.


## Синхронизация через GitHub

В меню приложения есть пункт **«Синхронизация GitHub»**. Приложение может автоматически создать приватный репозиторий `debtsavings-sync` (имя можно изменить) и хранить там одну зашифрованную копию всех кредитов, операций, подписок и настроек. Локальная работа без интернета сохраняется.

### Подключение

1. В приложении откройте **Синхронизация GitHub → Подключить GitHub → Создать токен**.
2. Создайте Personal Access Token. Для Fine-grained token укажите доступ к репозиториям и разрешение **Contents: Read and write**. Для автоматического создания репозитория также нужно **Administration: Read and write**. Альтернатива: заранее создайте приватный репозиторий вручную и выдайте токену доступ только к нему. Классический токен может использовать scope `repo`.
3. Вставьте токен, задайте имя приватного репозитория и придумайте отдельный пароль синхронизации длиной от 8 символов.
4. На втором устройстве подключите тот же GitHub-репозиторий, введите свой токен с доступом к нему и **тот же пароль синхронизации**.

Токен и пароль сохраняются на устройстве в зашифрованном виде с помощью Android Keystore. В облако отправляется только зашифрованный AES-256-GCM файл; пароль для расшифровки не загружается. Забытого пароля сервер восстановить не сможет. Храните его отдельно.

### Как работает синхронизация

- После изменения данных — отложенный запуск примерно через 30 секунд.
- Дополнительная проверка — примерно раз в час при наличии сети.
- Есть ручная синхронизация, принудительная загрузка данных телефона и восстановление копии из GitHub.
- Если данные одновременно изменены на двух устройствах, автоматическая синхронизация останавливается и показывает конфликт. Выберите направление вручную: перед заменой облачная версия сохраняется в `conflicts/`, а перед восстановлением текущие данные телефона сохраняются в локальную зашифрованную копию.
- GitHub хранит историю коммитов, но не считайте её единственной резервной копией: периодически проверяйте восстановление.

Не публикуйте токен и не используйте один пароль синхронизации на посторонних сервисах. Удаление приложения или потеря доступа к Android Keystore может потребовать повторного ввода токена; для нового телефона всегда нужен пароль синхронизации.

## Полезные материалы

- [Банк России — Финансовая культура](https://fincult.info/) — материалы о кредитах, досрочном погашении, вкладах и финансовом планировании.
- [CFPB — стратегии погашения долга](https://www.consumerfinance.gov/documents/5782/cfpb_ymyg-toolkit_reducing-debt-worksheet.pdf) — сравнение «лавины» и «снежного кома».
- [CFPB — резервный фонд](https://www.consumerfinance.gov/an-essential-guide-to-building-an-emergency-fund/) — выбор персональной цели, регулярные взносы и мониторинг прогресса.
- [CFPB — приоритет платежей](https://files.consumerfinance.gov/f/documents/cfpb_your-money-your-goals_prioritizing-bills_tool.pdf) — оценка последствий просрочки и приоритет жилья, дохода, страхования и обязательств.
